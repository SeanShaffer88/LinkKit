# LinkKit — agent notes

- **The vtable slots and GUIDs in `src/platform.rs` were verified against the `windows` crate 0.62.2 generated bindings** (IShellLinkW_Vtbl, IPersistFile_Vtbl, IPropertyStore_Vtbl, the ShellLink class id, and PKEY_AppUserModel_ID — projected under `Windows::Win32::Storage::EnhancedStorage`). Vtables are ABI: a wrong slot calls the wrong method silently. Never edit a slot constant or GUID from memory; re-check the bindings (they live in the local cargo registry) and update the citation comment in the same change.
- **Stamp before save is load-bearing.** The AppUserModelID is set through the link object's `IPropertyStore` and committed *before* `IPersistFile::Save` — that is what writes the property into the file (the sequence MuseDesktop's `AppUserModelId` uses). Setting the property after the final save persists nothing.
- **Never load-then-save an unloaded link in `lk_create`.** Create builds a fresh link from the spec; `lk_set_app_id` is the load-existing path, and it must always Load before it stamps and saves — saving an unloaded link would overwrite the user's shortcut with an empty one.
- **Validation happens in the core, before any COM call, on every platform** — and the platform layer trusts it (paths arrive absolute, the icon index fits an i32, the app id is well-formed). New spec fields get their validation in `src/lib.rs` with tests, not in the COM layer.
- **ole32 is resolved dynamically; there are no COM import libraries.** Do not add a `#[link]` for ole32/shell32 or a `windows` crate dependency to "simplify" the COM code — the zero-dependency, no-new-link-deps shape is deliberate (the ShellKit jump-list precedent).
- **`app_id: null` vs `""` is a contract.** Only the property store can distinguish an absent AppUserModelID, so only `app_id` is nullable in the read result. Do not "normalize" the other string fields to null — the getters genuinely cannot tell.
- **GetValue results are cleared with PropVariantClear before anything else happens** (including error returns). Skipping the clear leaks the store's CoTaskMem string per read.
- The JSON engine (src/json.rs) is the family design — duplicate keys in one object are a PARSE ERROR by design; do not "fix" that into last-wins.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate, and the Windows-only integration test in `src/ffi.rs` only runs there; the COM runtime stays Unverified until a field test (see QUALITY.md).
